## User Scenarios & Testing *(mandatory)*

### User Story 1 - 60초 안에 지원자 파악하기 (Priority: P1)

채용 담당자가 지원서나 메시지에 첨부된 링크를 눌러 이 페이지에 처음 들어온다. 스크롤하기 전에
이름, 어떤 개발자인지, 경력 연차, 대표 기술이 한눈에 들어온다. 더 볼 가치가 있는지를 몇 초 안에
판단하고, 관심이 생기면 바로 연락 경로를 찾는다.

**Why this priority**: 이 페이지의 존재 이유 자체다. 방문자의 첫 화면에서 판단이 끝나는 경우가
대부분이므로, 나머지 이력이 아무리 충실해도 이 요약이 없으면 전달되지 않는다. 이 스토리만
구현해도 "내 소개 링크"로 공유할 수 있는 완결된 산출물이 된다.

**Independent Test**: 이 페이지 URL만 전달받은 사람에게 60초를 주고, 지원자의 이름·직군·경력
연차·핵심 기술을 말해보게 하여 검증할 수 있다. 다른 페이지나 파일 없이 단독으로 성립한다.

**Acceptance Scenarios**:

1. **Given** 방문자가 페이지 URL로 처음 진입했고, **When** 스크롤하지 않은 상태에서 화면을 보면,
   **Then** 이름, 직함, 한 줄 소개, 연락 경로가 모두 보인다.
2. **Given** 방문자가 320px 폭의 모바일 화면을 쓰고 있고, **When** 페이지를 열면,
   **Then** 가로 스크롤 없이 같은 정보가 읽히는 크기로 표시된다.
3. **Given** 방문자가 마우스 없이 키보드만 사용하고, **When** Tab 키로 이동하면,
   **Then** 모든 링크와 버튼에 보이는 초점 표시와 함께 순서대로 도달한다.
4. **Given** 프로필 이미지가 로드되지 않았고, **When** 페이지를 보면,
   **Then** 레이아웃이 무너지거나 내용이 밀리지 않고 대체 텍스트가 제공된다.

### User Story 2 - 경력과 이력 훑어보기 (Priority: P2)

첫 화면에서 관심이 생긴 방문자가 아래로 내려가며 경력 사항을 확인한다. 어디서 얼마 동안 어떤
역할을 했고 무엇을 만들었는지를 최신 순서로 훑고, 기술 스택이 실제 경험과 어떻게 연결되는지 본다.

**Why this priority**: 판단의 근거를 제공하는 부분이다. 다만 P1의 요약이 없으면 여기까지 내려오는
방문자 자체가 생기지 않으므로 두 번째다.

**Independent Test**: 경력·학력 항목이 채워진 상태에서 페이지를 열어, 각 항목의 기간·조직·역할·성과가
최신순으로 읽히는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 경력 항목이 여러 개 등록되어 있고, **When** 경력 영역을 보면,
   **Then** 최신 항목이 가장 위에 오고 각 항목에 조직명, 역할, 기간, 주요 성과가 표시된다.
2. **Given** 특정 이력 유형(예: 수상, 자격증)에 등록된 항목이 하나도 없고, **When** 페이지를 보면,
   **Then** 해당 영역 자체가 표시되지 않는다.
3. **Given** 현재 재직 중인 항목이 있고, **When** 그 항목의 기간을 보면,
   **Then** 종료일 대신 재직 중임이 드러난다.

### User Story 3 - 이력서 내려받기와 연락하기 (Priority: P3)

방문자가 채용 절차에 필요한 이력서 파일을 내려받거나, 이메일 또는 코드 저장소 링크로 이동한다.
또는 페이지를 그대로 인쇄하거나 PDF로 저장해 내부에 공유한다.

**Why this priority**: 실제 연락으로 이어지는 마지막 단계지만, 앞의 두 스토리 없이는 도달하지
않는다. 연락 경로 자체는 P1에 포함되며 여기서는 파일과 인쇄 형태를 다룬다.

**Independent Test**: 이력서 내려받기를 실행해 파일이 열리는지, 인쇄 미리보기에서 내용이 잘리지
않는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 방문자가 이력서 내려받기를 선택하면, **When** 동작이 완료되면,
   **Then** 최신 이력서 파일이 열리거나 저장된다.
2. **Given** 방문자가 페이지를 인쇄하거나 PDF로 저장하면, **When** 결과물을 보면,
   **Then** 내비게이션 같은 화면 전용 요소가 빠지고 본문이 잘리지 않는다.
3. **Given** 방문자가 이메일 주소를 확인하려 하면, **When** 연락 영역을 보면,
   **Then** 사람이 읽고 복사할 수 있는 형태로 제공된다.

### Edge Cases

- 아직 경력 항목이 하나도 없는 상태(신입)에서는 어떻게 보이는가? → 빈 영역은 숨겨지고 학력·프로젝트
  중심으로 페이지가 성립해야 한다.
- 조직명이나 직함이 아주 길 때 좁은 화면에서 넘치거나 잘리지 않는가?
- 이력서 파일이 아직 준비되지 않았을 때 내려받기 경로는 어떻게 처리되는가? → 링크를 노출하지 않는다.
- 외부 링크(코드 저장소 등)가 더 이상 유효하지 않을 때 방문자에게 어떤 경험이 되는가?
- 화면 낭독기 사용자가 들을 때 정보 순서가 시각적 순서와 어긋나지 않는가?
- 시스템이 어두운 테마로 설정된 방문자에게도 모든 글자가 읽히는 대비를 유지하는가?
- 매우 넓은 화면에서 한 줄의 글자 수가 지나치게 길어져 가독성이 떨어지지 않는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 페이지는 이름, 직함, 한 줄 소개, 프로필 이미지로 구성된 소개 영역을 최상단에 표시해야 한다.
- **FR-002**: 페이지는 연락 경로(이메일 및 코드 저장소 등 외부 프로필 링크)를 첫 화면에서 확인할 수
  있는 위치에 표시해야 한다.
- **FR-003**: 페이지는 보유 기술을 분류(예: 언어, 프레임워크, 도구)별로 묶어 표시해야 한다.
- **FR-004**: 페이지는 경력 이력을 최신순으로 표시해야 하며, 각 항목은 조직명, 역할, 기간, 주요 성과를
  포함해야 한다.
- **FR-005**: 페이지는 학력 및 교육·자격 이력을 표시해야 한다.
- **FR-006**: 종료일이 없는 이력 항목은 현재 진행 중임이 드러나도록 표시해야 한다.
- **FR-007**: 등록된 항목이 없는 영역은 제목을 포함해 전체가 숨겨져야 한다.
- **FR-008**: 이력서 파일이 등록되어 있을 때 페이지는 내려받기 경로를 제공해야 하며, 등록되어 있지
  않으면 해당 경로를 노출하지 않아야 한다.
- **FR-009**: 모든 이력 콘텐츠는 저장소 안의 구조화된 텍스트로 관리되어야 하며, 항목 추가·수정이
  화면 구성 코드 변경 없이 가능해야 한다.
- **FR-010**: 페이지는 인쇄 및 PDF 저장 시 화면 전용 요소를 제외하고 본문이 잘리지 않게 출력되어야 한다.
- **FR-011**: 페이지는 공유 시 제목, 요약 설명, 미리보기 이미지가 노출되도록 메타 정보를 제공해야 한다.
- **FR-012**: 페이지는 이름과 직군을 담은 문서 제목을 가져야 하며, 검색 엔진이 수집할 수 있어야 한다.
- **FR-013**: 페이지는 프로젝트 헌장의 접근성(원칙 II)과 성능(원칙 III) 기준을 충족해야 하며, 두 기준의
  자동 검사를 통과해야 한다.
- **FR-014**: 모든 텍스트 콘텐츠는 한국어로 제공되어야 하며, 문서의 언어가 한국어임이 명시되어야 한다.

### Key Entities

- **프로필**: 사이트 주인을 나타내는 단일 항목. 이름, 직함, 한 줄 소개, 프로필 이미지, 연락 경로 목록,
  이력서 파일 참조를 가진다.
- **경력 항목**: 하나의 재직·참여 이력. 조직명, 역할, 시작일, 종료일(없으면 진행 중), 성과 목록을 가진다.
- **학력·교육 항목**: 하나의 교육 이수 이력. 기관명, 과정명, 기간, 비고를 가진다.
- **기술 항목**: 하나의 기술 역량. 이름과 소속 분류를 가진다.
- **외부 링크**: 표시 이름, 대상 주소, 종류(이메일/저장소/기타)를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 페이지를 처음 본 사람 5명 중 4명 이상이 60초 안에 이름, 직군, 경력 연차, 대표 기술
  3가지를 정확히 말할 수 있다.
- **SC-002**: 320px부터 1920px까지 모든 화면 폭에서 가로 스크롤 없이 첫 화면에 한 줄 소개와 연락
  경로가 보인다.
- **SC-003**: 방문자가 이력서 파일을 얻거나 이메일 주소를 확인하기까지 2번 이하의 조작이 필요하다.
- **SC-004**: 키보드만으로 페이지의 모든 상호작용 요소에 도달할 수 있으며, 접근성 자동 검사에서
  위반이 0건이다.
- **SC-005**: 일반적인 모바일 환경에서 방문자가 2.5초 안에 페이지의 주요 내용을 볼 수 있고, 읽는
  도중 내용이 밀려 움직이지 않는다.
- **SC-006**: 새로운 경력 항목 하나를 추가하는 데 콘텐츠 파일 1개만 수정하면 되고 10분 이내에 끝난다.
- **SC-007**: 페이지를 A4로 인쇄했을 때 2장 이내에 담기고 잘리는 내용이 없다.
- **SC-008**: 밝은 테마와 어두운 테마 모두에서 모든 텍스트가 대비 기준을 충족한다.

## Assumptions

- 이 페이지는 사이트 주인 한 사람의 이력만 다루며, 방문자용 로그인이나 웹 편집 화면은 범위에 없다.
- 이력 데이터는 사이트 주인이 저장소의 콘텐츠 파일을 직접 수정해 관리한다.
- 모든 콘텐츠는 한국어 전용이며, 다국어 전환은 범위에 없다.
- 이력서 파일은 별도로 준비해 저장소에 올리는 정적 파일로 가정하며, 페이지가 자동 생성하지 않는다.
- 홈 페이지와 프로젝트 상세 페이지는 아직 없으므로, 이 페이지는 사이트 최상위 주소에서 단독으로
  접근 가능해야 한다. 이후 홈이 추가되면 별도 경로로 옮기는 것은 다음 기능에서 다룬다.
- 프로필 이미지 1장이 준비되어 있다고 가정한다.
- 방문자 추적 목적의 외부 분석 도구나 임베드는 헌장의 제약에 따라 포함하지 않는다.
- 문의 폼처럼 방문자 입력을 받는 기능은 이 기능의 범위가 아니며, 연락은 이메일과 외부 링크로만 이뤄진다.
- 이 페이지에서 정의되는 색상·간격·타이포그래피 토큰은 헌장 원칙 V에 따라 이후 페이지에서 재사용된다.
