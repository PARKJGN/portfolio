# Phase 1 — 데이터 모델

**Feature**: 방·책장·책 모달 골격 | **Date**: 2026-07-22

데이터베이스는 없다. 모든 것은 저장소 안의 마크다운 파일이며, 빌드 시 읽어 정적 페이지로 굽는다.
아래 스키마는 Zod로 검증하고, 검증 실패는 **빌드 실패**로 처리한다 — 잘못된 콘텐츠가 배포되는 것보다
빌드가 멈추는 편이 낫다.

## 엔터티 개요

```
방 (암묵적 · 파일 없음)
└── 책장 Shelf  (3개, content/shelves/*.md)
    └── 책 Book  (content/books/<shelf>/*.md)
        └── 장 Section  (책 본문 안의 구분)
```

"보기 방식"은 콘텐츠가 아니라 방문자의 상태이므로 파일이 아니라 브라우저에 저장한다.

---

## Shelf (책장)

**위치**: `src/content/shelves/<slug>.md`

| 필드 | 타입 | 필수 | 규칙 |
|---|---|---|---|
| `slug` | string | ✓ | 파일명에서 유도. 소문자·하이픈만. 전체에서 고유 |
| `name` | string | ✓ | 방에 표시되는 이름. 프로필 / 프로젝트 / 방명록 |
| `order` | number | ✓ | 방에서의 배치 순서. 1부터 |
| `description` | string | ✓ | 낭독기와 빈 상태 안내에 쓰인다 |
| `emptyMessage` | string | | 소속 책이 0권일 때 표시할 문구. 없으면 기본 문구 |

**규칙**
- 책장은 정확히 3개여야 한다 (FR-001). 개수가 다르면 빌드 실패.
- `order`는 1, 2, 3이 각각 하나씩 있어야 한다. 중복·누락 시 빌드 실패.
- 소속 책이 0권이어도 책장은 존재한다. 이 경우 방에서 "비어 있음"으로 표시하고 열 수 없다 (FR-014).

## Book (책)

**위치**: `src/content/books/<shelf-slug>/<slug>.md`
디렉터리가 소속 책장을 결정한다 — 프론트매터에 책장을 또 적지 않는다(어긋날 여지를 없앤다).

| 필드 | 타입 | 필수 | 규칙 |
|---|---|---|---|
| `slug` | string | ✓ | 파일명에서 유도. URL `/books/<slug>`가 된다. **전체에서 고유** |
| `title` | string | ✓ | 책등과 창 제목에 쓰인다 |
| `order` | number | ✓ | 책장 안에서의 순서. 같은 책장 안에서 고유 |
| `spineColor` | token | ✓ | 책등 배경. 토큰 이름만 허용(리터럴 hex 금지 — 원칙 V) |
| `spineTextColor` | token | ✓ | 책등 글자. `spineColor`와 짝을 이루는 토큰 |
| `spineHeight` | enum | ✓ | `short` \| `medium` \| `tall`. 책장의 자연스러움을 위한 변주 |
| `spineWidth` | enum | ✓ | `narrow` \| `medium` \| `wide` |
| `year` | string | | 책등 상단 표시 |
| `callNumber` | string | | 책등 하단의 청구기호풍 표기 |
| `summary` | string | ✓ | 공유 미리보기 설명과 낭독기 요약에 쓰인다 |
| *(본문)* | markdown | ✓ | 책 내용. 아래 Section 참조 |

**규칙**
- `slug`는 책장을 가로질러 전체에서 고유해야 한다. URL이 `/books/<slug>`로 평평하기 때문이다.
  중복 시 빌드 실패.
- `spineColor` / `spineTextColor` 조합은 **대비 4.5:1 이상**이어야 한다. 토큰 쌍을 미리 검증된
  목록으로 제한해 이를 보장한다(`design-notes.md`의 9종). 목록 밖의 조합은 빌드 실패.
- 본문이 비어 있으면 빌드 실패. 빈 책은 존재할 수 없다 — 빈 것은 책장 단위로만 허용된다.
- 001에서는 프로필 책장에 본문을 가진 책이 최소 1권 있어야 한다 (FR-022). 없으면 빌드 실패.

## Section (장)

**표현 방식**: 별도 파일이 아니라 책 본문 안의 논리적 단위다.

`R-2`의 결정에 따라 **장 나눔은 CSS가 화면 크기에 맞춰 수행**한다. 따라서 콘텐츠에는 "몇 번째 장"이
고정되어 있지 않다. 저자는 문서를 쓰고, 브라우저가 화면에 맞게 나눈다.

| 개념 | 표현 |
|---|---|
| 장 제목 | 마크다운 `##` 제목 |
| 장 경계 | 지정하지 않음. 브라우저가 결정 |
| 반드시 붙어 있어야 하는 덩어리 | 표·이미지·인용 — `break-inside: avoid`로 단 경계를 넘지 않게 한다 |

**결과**: "한 장씩 넘기기"와 "전체 이어보기"는 같은 문서에 CSS만 다르게 적용한 두 표현이다.
낭독기와 검색 엔진에는 언제나 하나의 연속된 문서로 보인다.

## ViewMode (보기 방식)

**저장 위치**: 브라우저 `localStorage`. 서버도 파일도 관여하지 않는다.

| 항목 | 값 |
|---|---|
| 키 | `book-view-mode` |
| 값 | `paged` (한 장씩) \| `continuous` (전체 이어보기) |
| 기본값 | `paged` — 시안의 책 은유를 첫인상으로 준다 |
| 유효 범위 | 같은 방문 중 모든 책에 적용 (FR-009) |

**상태 전이**

```
paged ⇄ continuous        전환 1회 조작 (FR-008)
```

- 값이 없거나 알 수 없는 값이면 기본값으로 되돌린다.
- `prefers-reduced-motion`이 켜져 있어도 기본값은 `paged`다. 다만 넘김 연출만 생략한다 (FR-016).
  읽는 방식을 사용자 대신 바꾸지 않는다.
- `localStorage`를 쓸 수 없는 환경(사생활 보호 모드 등)에서는 기본값으로 동작하고 오류를 내지 않는다.

## 파생 데이터 (빌드 시 계산)

| 값 | 계산 방법 | 용도 |
|---|---|---|
| 책장별 책 목록 | 디렉터리 기준으로 묶고 `order` 정렬 | 방 렌더링 |
| 책의 소속 책장 | 파일 경로에서 유도 | 책 페이지의 돌아가기 링크 |
| 이전/다음 책 | 같은 책장 안 `order` 기준 | 책 페이지 간 이동 |
| 사용된 글자 집합 | 모든 콘텐츠의 문자 수집 | 폰트 서브셋 (R-4) |
| 정적 경로 목록 | 모든 책의 `slug` | `generateStaticParams` |
