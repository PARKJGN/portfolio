# Feature Specification: 방·책장·책 모달 골격

**Feature Branch**: `001-room-bookshelf-shell`

**Created**: 2026-07-21

**Status**: Draft

**Input**: User description: "방 안에 책장 3개(프로필, 포트폴리오, 방명록). 책을 누르면 책 모양 모달로 내용을 보여준다. 한 장씩 넘기는 방식과 전체를 한 번에 보여주는 방식 둘 다 필요하다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방에 들어와 책을 열어보기 (Priority: P1)

방문자가 링크로 들어오면 책장 세 개가 놓인 방이 보인다. 각 책장이 무엇에 관한 것인지(프로필,
프로젝트, 방명록) 설명 없이도 알아본다. 관심 가는 책을 누르면 책 모양의 창이 열리고 그 안에서
내용을 읽는다. 다 읽으면 창을 닫고 방으로 돌아와 다른 책을 고른다.

**Why this priority**: 이 사이트의 정체성 자체다. "방 → 책장 → 책 → 내용"이라는 탐색 흐름이
성립하지 않으면 어떤 콘텐츠를 넣어도 전달되지 않는다. 프로필 책 한 권만 실제 내용으로 채워도
방문자에게 보여줄 수 있는 완결된 사이트가 된다.

**Independent Test**: 사전 설명 없이 링크만 받은 사람에게 "자기소개를 찾아보라"고 요청해,
안내 없이 책장을 고르고 책을 열어 내용에 도달하는지 관찰하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 방문자가 처음 진입했고, **When** 화면을 보면,
   **Then** 책장 세 개와 각 책장의 주제가 구분되어 보인다.
2. **Given** 방문자가 책 하나를 선택하고, **When** 열리면,
   **Then** 책 모양의 창 안에 해당 책의 내용이 표시되고 방은 뒤로 물러난다.
3. **Given** 책 창이 열려 있고, **When** 닫기를 실행하면(닫기 버튼, 바깥 영역, Esc 중 무엇이든),
   **Then** 방으로 돌아오고 직전에 열었던 책 위치에 초점이 남는다.
4. **Given** 아직 내용이 준비되지 않은 책장이 있고, **When** 방문자가 그 책장을 보면,
   **Then** 비어 있음이 드러나 헛된 클릭을 유도하지 않는다.
5. ~~**Given** 방문자가 특정 책이 열린 주소를 공유받았고, **When** 그 주소로 들어오면,
   **Then** 해당 책이 열린 상태로 시작한다.~~ (삭제됨 — 헌장 3.0.0, 책별 딥링크 미제공)

### User Story 2 - 읽는 방식 고르기 (Priority: P2)

책을 펼친 방문자가 읽기 방식을 고른다. 책장을 한 장씩 넘기며 보는 방식은 실제 책을 읽는 느낌을
주고, 전체를 한 번에 이어서 보는 방식은 원하는 대목을 빠르게 찾거나 훑어보기에 좋다. 한 번 고른
방식은 다른 책을 열 때도 유지된다.

**Why this priority**: 넘기는 연출은 이 사이트의 재미지만, 정보를 얻으러 온 사람에게는 방해가 될
수 있다. 두 방식을 모두 제공해야 "구경하러 온 사람"과 "정보를 찾으러 온 사람"을 동시에 만족시킨다.
다만 P1의 탐색 흐름이 없으면 성립하지 않으므로 두 번째다.

**Independent Test**: 책을 연 뒤 두 방식을 번갈아 전환하며 같은 내용이 빠짐없이 보이는지, 다른
책을 열었을 때 선택이 유지되는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 책이 한 장씩 넘기는 방식으로 열려 있고, **When** 다음으로 넘기면,
   **Then** 다음 내용이 나타나고 현재 위치와 전체 분량을 알 수 있다.
2. **Given** 방문자가 전체 보기로 전환하면, **When** 전환이 끝나면,
   **Then** 책의 모든 내용이 이어진 형태로 표시되고 처음부터 끝까지 훑을 수 있다.
3. **Given** 방문자가 전체 보기를 선택한 상태에서, **When** 다른 책을 열면,
   **Then** 그 책도 전체 보기로 열린다.
4. **Given** 방문자가 마지막 장을 보고 있고, **When** 다음으로 넘기려 하면,
   **Then** 끝에 도달했음이 드러나고 다음 동작(닫기 등)이 안내된다.
5. **Given** 방문자가 움직임 최소화를 설정해 두었고, **When** 장을 넘기면,
   **Then** 넘김 연출 없이 내용만 즉시 바뀐다.

### User Story 3 - 마우스 없이, 작은 화면에서도 읽기 (Priority: P3)

키보드만 쓰는 방문자, 화면 낭독기를 쓰는 방문자, 좁은 휴대폰 화면으로 들어온 방문자가 같은 내용에
도달한다. 공간 연출을 즐기지 못하더라도 정보 접근에서 손해를 보지 않는다.

**Why this priority**: 헌장 원칙 II에 따라 타협 대상이 아니다. 별도 스토리로 둔 이유는 이 경로가
독립적으로 검증되어야 하기 때문이며, 실제로는 P1·P2 구현과 함께 만들어진다.

**Independent Test**: 마우스를 뽑고 키보드만으로 방 진입부터 특정 책의 마지막 장까지 도달해 보고,
낭독기로 같은 경로를 따라가면 검증된다.

**Acceptance Scenarios**:

1. **Given** 방문자가 키보드만 사용하고, **When** 방에서 이동하면,
   **Then** 모든 책에 보이는 초점 표시와 함께 도달할 수 있고 선택해 열 수 있다.
2. **Given** 책 창이 열려 있고, **When** 키보드로 계속 이동하면,
   **Then** 초점이 창 밖의 방으로 새어 나가지 않는다.
3. **Given** 방문자가 320px 폭 화면을 쓰고, **When** 책을 열면,
   **Then** 가로 스크롤 없이 본문이 읽히는 크기로 표시된다.
4. **Given** 방문자가 좁은 화면에서 키보드만 쓰고, **When** 책장 사이를 이동하면,
   **Then** 넘기기 동작 없이도 다음 책장에 도달할 수 있다.
5. **Given** 화면 낭독기 사용자가 방에 들어오고, **When** 페이지를 훑으면,
   **Then** 책장과 책이 각각 무엇인지 이름으로 구분되어 전달된다.

### Edge Cases

- 좁은 화면에서 양면 펼침이 들어가지 않을 때 한 면씩 보여주는가?
- 책 한 권의 내용이 아주 길 때 한 장씩 보기에서 몇 장으로 나뉘는가?
- 창 크기를 바꿔 장 나눔이 다시 계산될 때 읽던 위치를 잃지 않는가?
- 책 창이 열린 상태에서 브라우저 뒤로 가기를 누르면 방으로 돌아오는가, 사이트를 떠나는가?
- 방 배경 이미지가 로드되지 않으면 책장과 책을 여전히 찾을 수 있는가?
- 아직 내용이 없는 책장(프로젝트, 방명록)을 눌렀을 때 방문자가 고장으로 오해하지 않는가?
- 매우 넓은 화면에서 방이 지나치게 늘어나 책이 작아지지 않는가?
- 어두운 테마에서 책 제목과 본문이 모두 읽히는 대비를 유지하는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 첫 화면은 책장 세 개가 배치된 방을 표시해야 한다.
- **FR-002**: 각 책장은 주제(프로필, 프로젝트, 방명록)가 방문자에게 식별되도록 표시되어야 한다.
- **FR-003**: 각 책장은 그 책장에 속한 책들을 표시해야 하며, 각 책은 제목으로 구분되어야 한다.
- **FR-004**: 방문자가 책을 선택하면 책 모양의 창이 열려 해당 책의 내용을 표시해야 한다.
- **FR-005**: 책 창은 닫기 버튼, 바깥 영역 선택, Esc 키 중 어느 방법으로도 닫을 수 있어야 한다.
- **FR-006**: 책 창이 닫히면 직전에 열었던 책 위치로 초점이 돌아가야 한다.
- **FR-007**: 책 창은 "한 장씩 넘기기"와 "전체 이어보기" 두 가지 보기 방식을 제공해야 한다.
- **FR-008**: 방문자는 책 창 안에서 한 번의 조작으로 두 보기 방식을 전환할 수 있어야 한다.
- **FR-009**: 선택한 보기 방식은 같은 방문 중 다른 책을 열 때도 유지되어야 한다.
- **FR-010**: 한 장씩 넘기기 방식은 현재 위치와 전체 분량을 표시해야 하며, 앞뒤 이동 수단을 제공해야 한다.
- **FR-011**: 전체 이어보기 방식은 해당 책의 모든 내용을 빠짐없이 하나의 흐름으로 표시해야 한다.
- **FR-012**: ~~특정 책이 열린 상태를 주소로 공유할 수 있어야 하며, 그 주소로 진입하면 해당 책이 열린
  상태로 시작해야 한다.~~ **삭제됨(헌장 3.0.0).** 책은 JS 3D/모달 리더로만 열리며 책별 딥링크·정적
  페이지를 제공하지 않는다. 열린 상태에서 뒤로 가기는 방으로 돌아오는 용도로만 남는다.
- **FR-013**: 책 창이 열려 있는 동안 키보드 초점은 창 안에 머물러야 한다.
- **FR-014**: 내용이 등록되지 않은 책장은 비어 있음이 드러나야 하며, 선택해도 빈 창을 열지 않아야 한다.
- **FR-015**: 모든 책과 책장의 내용은 저장소 안의 구조화된 텍스트로 관리되어야 하며, 책 추가·수정이
  화면 구성 코드 변경 없이 가능해야 한다.
- **FR-016**: 방문자가 움직임 최소화를 설정한 경우 넘김·전환 연출을 생략하고 결과 상태만 표시해야 한다.
- **FR-017**: 방과 책 창은 320px부터 넓은 화면까지 페이지 자체의 가로 스크롤 없이 이용 가능해야 한다.
- **FR-018**: 책장 세 개가 한 화면에 들어가지 않는 좁은 화면에서는 방문자가 책장 사이를 옆으로
  넘겨 이동할 수 있어야 하며, 현재 몇 번째 책장을 보고 있는지 알 수 있어야 한다.
- **FR-019**: 책장 사이 이동은 넘기기 동작뿐 아니라 키보드로도 가능해야 한다.
- **FR-020**: 페이지는 프로젝트 헌장의 접근성(원칙 II)과 성능(원칙 III) 기준을 충족해야 하며, 두 기준의
  자동 검사를 통과해야 한다.
- **FR-021**: 모든 텍스트 콘텐츠는 한국어로 제공되어야 하며, 본문용 글꼴은 한글 글리프를 포함해야 한다.
- **FR-022**: 이 기능에서는 프로필 책장에 실제 내용을 가진 책이 최소 1권 존재해야 하며, 이를 통해
  전체 흐름이 검증 가능해야 한다.

### Key Entities

- **방**: 책장들을 담는 최상위 공간. 배경 표현과 책장 배치 정보를 가진다.
- **책장**: 주제 하나를 담당하는 묶음. 이름(프로필/프로젝트/방명록), 설명, 소속 책 목록을 가진다.
- **책**: 하나의 읽을거리. 제목, 표지 표현, 순서, 내용(장의 나열)을 가진다.
- **장(페이지)**: 책 내용의 한 단위. 순서와 본문을 가진다.
- **보기 방식**: 방문자의 읽기 방식 선택. "한 장씩" 또는 "전체 이어보기" 중 하나이며 방문 중 유지된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사전 설명 없이 링크만 받은 사람 5명 중 4명 이상이 10초 안에 책 하나를 열 수 있다.
- **SC-002**: 사전 설명 없이 링크만 받은 사람 5명 중 4명 이상이 세 책장의 주제를 각각 맞힐 수 있다.
- **SC-003**: 방문자는 한 번의 조작으로 두 보기 방식을 전환할 수 있고, 전환 후에도 읽던 내용이 그대로
  보인다.
- **SC-004**: 키보드만으로 방 진입부터 임의의 책 마지막 장까지 도달할 수 있으며, 접근성 자동 검사에서
  위반이 0건이다.
- **SC-005**: 320px부터 1920px까지 모든 화면 폭에서 가로 스크롤이 발생하지 않는다.
- **SC-006**: 일반적인 모바일 환경에서 방문자가 2.5초 안에 방의 주요 내용을 볼 수 있고, 책을 열고 닫는
  동안 화면이 밀려 움직이지 않는다.
- **SC-007**: 새 책 한 권을 추가하는 데 콘텐츠 파일 1개만 수정하면 되고 10분 이내에 끝난다.
- **SC-008**: ~~특정 책이 열린 주소를 다른 사람에게 전달했을 때, 받은 사람이 추가 조작 없이 같은 책을
  본다.~~ (삭제됨 — 헌장 3.0.0, FR-012 삭제에 따름)
- **SC-009**: 밝은 테마와 어두운 테마 모두에서 모든 텍스트가 대비 기준을 충족한다.

## Assumptions

- 공간 표현은 정적 이미지와 화면 구성으로 만들며, 실시간 3차원 렌더링은 이 기능의 범위가 아니다.
- 책장 세 개의 주제는 프로필, 프로젝트, 방명록으로 고정한다.
- 이 기능은 골격 검증까지만 담당한다. 프로필 책의 상세 콘텐츠 구성, 프로젝트 작품 상세, 방명록의
  글 작성·저장은 각각 별도 기능으로 분리한다.
- 방명록은 방문자 글쓰기가 필요해 저장소가 필요하지만, 이 기능에서는 빈 책장으로만 존재한다.
  저장 방식과 헌장 원칙 I의 예외 근거는 방명록 기능의 계획 단계에서 다룬다.
- 모든 콘텐츠는 한국어 전용이며 다국어 전환은 범위에 없다.
- 콘텐츠는 사이트 주인이 저장소의 파일을 직접 수정해 관리하며, 웹 편집 화면은 범위에 없다.
- 방문자 브라우저에서 동작하는 추적 스크립트나 서드파티 분석 도구는 헌장 제약에 따라 포함하지 않는다.
  방문 기록은 서버 접근 로그로만 남기며, 이는 방문자에게 아무 코드도 내려보내지 않으므로 이 기능의
  화면 동작에 영향을 주지 않는다. 구체적인 구성은 `research.md`의 R-9에 있다.
- 시각 방향은 도서관의 목재·양피지 계열로 정해졌다. 근거가 된 시안 분석과 그로부터 확정·유보된
  사항은 `design-notes.md`에 정리되어 있으며, 구체적인 토큰 값은 계획 단계에서 확정한다.
